# Server tools

Утилиты для Linux VPS. Сейчас доступно безопасное отключение IPv6 с цветным выводом, резервной копией и автоматическим откатом.

## Быстрый запуск

В существующем IPv4 SSH-подключении под root выполните:

```bash
curl -fLSs --retry 2 https://raw.githubusercontent.com/InkoParadox/server-tools/main/ipv6.sh -o /root/mist-ipv6-1766e755cb1a.sh && echo '1766e755cb1a5990fe940cd7afb0b39d4f612c77adfa616df7ec90c30ad5be1b  /root/mist-ipv6-1766e755cb1a.sh'|sha256sum -c - && bash /root/mist-ipv6-1766e755cb1a.sh
```

Команда полностью скачивает файл, проверяет SHA-256 и запускает его только при успехе обоих шагов. При HTTP-ошибке, неполной загрузке или несовпадении суммы скрипт не запускается.

Для кнопки Xshell 8 выберите «Отправить Строку» и добавьте буквальное `\r` в конце команды. Для обычной вставки в терминал этот суффикс не добавляется: нажмите Enter. Подтверждённое по скриншоту обрезание поля конкретной сборки: 30000 символов; эта команда содержит 290 символов без суффикса.

## Подтверждение и восстановление

Перед сетевыми изменениями инструмент создаёт backup и отдельный systemd watchdog. По умолчанию окно подтверждения составляет 240 секунд с начала применения. Если выведено AWAITING_CONFIRMATION/«ЖДЁТ», откройте новое внешнее IPv4 SSH-подключение к тому же серверу и порту и выполните напечатанную команду подтверждения. Локальная проверка SSH не заменяет новое подключение. До успешного подтверждения страховка остаётся активной.

После успешного повторного запуска выводится NOOP. Автоматической перезагрузки нет. Резервные копии сохраняются в /var/lib/mist-ipv6/tx-*; полный сетевой инструмент и его режимы --check, --status, --confirm, --restore доступны в сохранённом tool.sh соответствующей операции.

## Совместимость

Нужны root, Bash, Python >=3.8, systemd, iproute2 и getent; для Netplan/cloud-init нужен уже установленный PyYAML, для NetworkManager нужны nmcli и busctl. Автоматических установок нет. Выбор сетевого менеджера и конфигурации выполняется автоматически.

Автор комплекта проверял Netplan/networkd, прямой networkd, NetworkManager, ifupdown/ifupdown2, статический IPv4/DHCP4 и systemd-resolved на Ubuntu/Debian. Ограничения исходного отчёта сохраняются: полная boot-приёмка cloud-init + ifupdown2 остаётся PARTIAL; native ifcfg-rh, enforcing SELinux, отдельный DHCPv6-сервер и реальный трафик VPN-туннелей не подтверждены. Другие дистрибутивы и системы без systemd не объявляются поддержанными.

Docker, несколько интерфейсов, мосты, VLAN и VPN-интерфейсы сами по себе не требуют отказа. Реальная зависимость служб от IPv6 или неоднозначный источник настроек приводят к STOP до сетевой записи. Независимые network namespaces контейнеров не меняются.

## Версия и проверка целостности

Версия движка 2.1 исправляет остановку на стандартном локальном сокете chronyd `[::1]:323`. Исключение применяется только для UDP, если тот же процесс chronyd слушает `127.0.0.1:323`, его исполняемый файл распознан как chronyd и read-only запрос chronyc по IPv4 подтверждает выбранный IPv4-источник времени. Наличие текущего IPv6-источника, отсутствие выбранного IPv4-источника или невозможность проверки дают STOP. Конфиги chronyd и его процесс не меняются.

Для этого случая chronyc должен быть уже установлен. После применения и перед подтверждением IPv4-мониторинг и источники проверяются повторно: при отказе после apply вызывается прежний rollback, при отказе на confirm watchdog остаётся активным. Другие конкретные IPv6-listeners, IPv6-соединения, DNS и туннели сохраняют прежние проверки. Сам факт парных IPv4/IPv6-сокетов у произвольной службы не разрешает отключение.

Проверяется текущее состояние chronyd; клиенты сторонних приложений с жёстко заданным `::1` и будущие изменения DNS этим не доказываются безопасными. Поддержка любого сервера не заявляется.

SHA-256 встроенного сетевого исходника 2.1:

`3e1820b483d0c44e52800527d9cacd192712ce15acf0ca53d9ec148d07b95d2d`

SHA-256 распространяемого ipv6.sh:

`1766e755cb1a5990fe940cd7afb0b39d4f612c77adfa616df7ec90c30ad5be1b`

Цветное оформление работает отдельно от сетевого движка. Оно сохраняет код ошибки и различает ожидание подтверждения, окончательный успех, возврат и ошибку. Проверены точные байты исходника, Bash syntax, сохранение root700, checksum-before-exec и PTY-вывод на имитаторе движка. Эти проверки оформления не расширяют native-матрицу V2.

Для версии 2.1 добавлены 28 изолированных регрессионных тестов: запуск `python3 -B -m unittest discover -s tests -v`. Они проверяют распознавание chronyd, отказы зависимостей, повторный запуск NOOP, повторный контроль IPv4 и вызов restore при потере мониторинга после apply. Сокеты, менеджеры, systemd и sysctl в этих тестах подменены; backup-файлы создаются в отдельном временном каталоге. Полное восстановление сети, reboot и применение версии 2.1 на рабочей VPS не проверены. Native-проверка в среде подготовки недоступна: netlink и network namespaces запрещены. Прежняя матрица V2 выше относится к прежнему исходнику.

Публикация содержит только утилиту и инструкцию. Серверные конфиги, credentials, ключи, резервные копии и журналы инфраструктуры не публикуются. Наличие репозитория не означает, что новая версия применена на рабочем сервере.
