# Server tools

Автономная утилита отключения IPv6 на Linux VPS с backup, независимым systemd-откатом и проверкой нового SSH-подключения. Версия 2.2 подготовлена в draft/PR; main изменяется только после отдельного решения владельца.

## Запуск с ПК

```powershell
python -X utf8 ipv6_ssh.py server-217
```

Используется существующий root SSH-алиас, его ключ и проверка host key. Обёртка сохраняет и проверяет полный соседний `ipv6.sh` на сервере. После применения она закрывает первое SSH и открывает другой TCP с `ControlMaster=no`, `ControlPath=none`, затем подтверждает операцию. Окно по умолчанию 600 секунд. Пакеты не устанавливаются.

Проверка без изменений: `python -X utf8 ipv6_ssh.py server-217 --check`. Статус: `--status`. Восстановление: `--restore /var/lib/mist-ipv6/tx-...`. Существующие SSH-конфиги не редактируются. Для автоматизированных тестов можно передать `--ssh-config PATH` и `--ssh PATH`.

## Xshell и прямой SSH

Один `ipv6.sh` содержит сетевой движок и цветное представление; внешних Python-модулей проекта ему не требуется. Без аргументов он **применяет** изменения. Для проверки используйте `bash ipv6.sh --check`; доступны `--apply`, `--status`, `--confirm TRANSACTION`, `--restore TRANSACTION`, `--connection`, `--rollback-seconds 60..1800`.

Короткую команду для конкретного Git commit формирует `python tools/command.py --ref FULL_COMMIT_SHA --output Xshell.txt`. Команда сохраняет загрузку в уникальный root-only файл, проверяет полный SHA-256 до выполнения и сохраняет исходник. Буквальный суффикс `\r` предназначен только для поля «Отправить Строку». В обычном Bash его нужно убрать и нажать Enter. Прежние Base64-строки превышали лимит поля 30000 символов и больше не применяются.

При прямом применении окно по умолчанию 240 секунд начинается перед сетевыми записями. AWAITING_CONFIRMATION сообщает фактически оставшееся время. Подтвердить нужно через TCP, открытый после этого события, к тому же IPv4-адресу и порту сервера. Ранее открытый второй SSH и новый multiplex-канал старого TCP отклоняются. Обёртка с ПК выполняет этот шаг автоматически.

В tmux требуется нажать Enter в небольшом окне **того клиента**, через который подтверждается операция. Панель может хранить старое окружение: транспорт определяется по процессу клиента tmux и сокету sshd в ядре. При нескольких клиентах произвольный сокет не выбирается. Без клиента, при неоднозначности или отсутствии ответа за 20 секунд операция останавливается. Конфигурация tmux не меняется. Из root SSH вне tmux дополнительного Enter нет.

## Изменения 2.2

Проверка `SSH_CONNECTION` заменена доказательством фактического транспорта: inode сокета, четыре адресных поля, процесс sshd, время его создания и boot ID. Подтверждающий процесс проверяется повторно перед COMMITTED. Сохранены узкое исключение chronyd 2.1 и все сетевые адаптеры/проверки V2. Цветной интерфейс сохраняет exit code; при нетерминальном stdout выдаётся JSON. `MIST_IPV6_UI=stderr` добавляет цветной вывод в stderr, сохраняя JSON stdout.

STOP содержит отдельные коды: `ssh_same_transport`, `ssh_endpoint_changed`, `ssh_transport_predates_apply`, `ssh_transport_lost`, `confirmation_expired`, `not_awaiting_confirmation`, `server_rebooted`, `watchdog_inactive`, `legacy_transport_unproven`, а также причины неоднозначного SSH/tmux. Статус показывает оставшиеся секунды и активность страховки. Подтверждение транзакций 2.1 без доказательства транспорта запрещено; для их восстановления сохраняется совместимость. Истёкшую/откаченную операцию нельзя подтвердить задним числом.

## Сохранность сети

До сетевой записи создаются проверенные дубли backup и отдельный watchdog. Ошибки/сигналы ведут к restore, отсутствие подтверждения к автооткату. Транзакции защищены flock; чужие изменения файлов не перезаписываются. Backup сохраняется в `/var/lib/mist-ipv6/tx-*`, включая точный `tool.sh`, исходные файлы и состояние. Повторный успешный запуск возвращает NOOP. Автоматической перезагрузки, изменения загрузчика или Windows-служб нет.

IPv4, маршруты, DNS, MTU и остальные параметры сохраняются. DHCP lifetime нормализуется, потеря адреса/маршрута остаётся ошибкой. Работа ведётся только в host namespace. Docker, bridges, VLAN, bond и VPN сами по себе не вызывают STOP; реальная IPv6-зависимость, конфликт владельцев или неподдерживаемая схема дают конкретный отказ до записи. SSH/UFW, прикладные и контейнерные конфиги не редактируются.

## Фактически проверенная совместимость

Нужны root, Bash, Python >=3.8, systemd, iproute2 и getent. Для Netplan/cloud-init нужен уже установленный PyYAML; для NetworkManager нужны nmcli и busctl. Проверка нового транспорта выполнялась на Ubuntu 24.04, OpenSSH 9.6 и tmux 3.4, ядре Linux 6.8. Для других версий нельзя считать этот прогон подтверждением.

| Область | Доказательство версии 2.2 |
| --- | --- |
| Netplan/networkd + cloud-init, DHCP4, resolved | Настоящая Ubuntu VM: apply, новый SSH с ПК, COMMITTED, NOOP, restore, timeout |
| chronyd: парные 127.0.0.1/[::1]:323, источники IPv4 | Настоящий chronyd 4.5 + регрессии |
| SSH/tmux, endpoint, mux | Native-сценарии и raw evidence выдаются с комплектом; конкретные итоги указаны в отчёте |
| Слияние Netplan, direct networkd, NM keyfile, ifupdown/2, static/DHCP4, DNS, метаданные, отказы | 114 тестов текущего встроенного исходника; команды менеджеров в unit-тестах подменены |
| Остальные native-матрицы V2 | История другого SHA; не выдаётся за native-приёмку 2.2 |

Cloud-init + ifupdown2 boot остаётся PARTIAL. Native ifcfg-rh и enforcing SELinux не подтверждены. Другие дистрибутивы и системы без systemd не объявляются проверенными. Перезагрузка рабочей VPS требует отдельного GO; reboot выполняется только на одноразовой VM.

## Разработка и контрольные суммы

`src/engine.py`, `src/display.py` и `tools/engine-prefix.txt` являются читаемыми исходниками. `python tools/build.py` воспроизводимо собирает единственный автономный `ipv6.sh`; `--check` проверяет совпадение без записи. Встроенные байты Python сохраняют CRLF прежней версии, оболочка LF. Проверки: `python3 -B -m unittest discover -s tests -v` в Linux.

SHA-256 `ipv6.sh`: `3253de1cf5dfcb43fe4ac434cfd9ed05797eb5b0b93a89fff010ba079fede38c`.

Проверки unit используют подмены и не заменяют ядро/менеджер. Raw native evidence, снимки исходников, runners и серверные backups остаются в локальном комплекте; credentials и рабочие конфиги в GitHub не публикуются.
